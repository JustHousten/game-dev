Genau der Umfang, der weiter unten steht — nicht mehr. Bisherige Versuche sind daran gescheitert, dass der Anspruch immer weiter wuchs. Diesmal: klein, spielbar, fertig. Alles Weitere kommt erst, wenn dieser Kern läuft und Spaß macht.

01

Kernschleife

MapEine kleine, begehbare Fläche. Keine Segmente/Räume — eine zusammenhängende Arena.
Spieler-BewegungNur WASD. Kein Maus-Input nötig.
AutocombatAngriff läuft automatisch — wie in Brotato per Default. Cleave: alle Gegner innerhalb der Reichweite werden gleichzeitig getroffen.
AngriffMelee, mit spürbar größerer Reichweite als der Kontaktradius der Gegner. Feuert per Cooldown-Timer.
Gegner-SpawnSpawnt laufend; Rate/Anzahl steigt mit der verstrichenen Zeit.
SchadenGegner fügen Schaden zu, sobald ihre Hitbox den Spieler berührt.
02

03

Architektur-Skizze

Vorschlag zur Diskussion — Node-Struktur, kein finaler Bauplan.

Main (Node2D) ├─ Arena // Boden + Kollisions-Ränder ├─ Player (CharacterBody2D) │ ├─ Sprite2D │ ├─ Hurtbox (Area2D) // wird von Gegnern getroffen │ ├─ AttackRange (Area2D) // erkennt Gegner in Reichweite │ ├─ AttackTimer (Timer) // Cooldown, trifft bei jedem Tick ALLE Gegner in AttackRange (Cleave) │ └─ Camera2D ├─ EnemySpawner (Node2D + Timer) // wait_time sinkt über Zeit └─ Enemies (Node2D) // Container für Enemy-Instanzen └─ Enemy (CharacterBody2D) ├─ Sprite2D └─ Hitbox (Area2D) // Schaden bei Overlap mit Player-Hurtbox
04

Lernpfad & Umsetzungsreihenfolge

Jede Phase baut auf der vorherigen auf. Lern nur das, was die jeweils nächste Phase braucht — nicht mehr, nicht vorher.

PHASE 0

Editor kennenlernen

Godot 4.7 installieren, Szenen/Node-Konzept, Szenenbaum, Inspector, Projekt anlegen — noch kein Code.

EmpfehlungEinmal komplett das offizielle Einsteiger-Tutorial "Your First 2D Game" (Dodge the Creeps) aus der Godot-Doku durchspielen. Deckt fast dieselbe Grundmechanik ab (Spieler, Timer-Spawner, Kollisionen) — bevor ihr euer eigenes baut.

PHASE 1

Grundgerüst

Projekt + Ordnerstruktur anlegen, Arena-Szene (Boden + Rand-Kollision), Input Map für WASD in den Projekteinstellungen.

BrauchtSzenen erstellen/verschachteln, Input Map — kein Scripting nötig.

PHASE 2

Spieler-Bewegung

Spieler läuft mit WASD durch die Arena, Kamera folgt.

BrauchtCharacterBody2D, _physics_process(), Input.get_vector(), move_and_slide().

PHASE 3

Gegner-Bewegung

Enemy-Szene, die sich auf den Spieler zubewegt.

BrauchtRichtungsvektor berechnen (position.direction_to()), Referenz auf den Spieler-Node (z. B. über Gruppen).

PHASE 4

Spawner

EnemySpawner erzeugt laufend neue Enemy-Instanzen an zufälligen Randpositionen.

BrauchtTimer + timeout-Signal, PackedScene.instantiate(), add_child(), Zufallswerte.

PHASE 5

Kontaktschaden

Hurtbox am Spieler, Hitbox am Gegner — Berührung reduziert Spieler-HP (erstmal nur zum Testen ausgeben).

BrauchtArea2D/CollisionShape2D, Signale (body_entered), eigene signals, @export-Variablen.

PHASE 6

Autocombat (Cleave)

AttackRange + AttackTimer am Spieler — trifft automatisch alle Gegner in Reichweite.

BrauchtZweiten Timer als Cooldown, get_overlapping_bodies(), for-Schleife, Methodenaufruf auf fremden Nodes.

PHASE 7

Tod & Zustände

Gegner verschwinden bei 0 HP, Spieler stirbt/startet neu bei 0 HP.

BrauchtBedingungen (if health <= 0), queue_free(), Szene neu laden.

PHASE 8

Steigende Schwierigkeit

Spawner wird über die Zeit schneller/mehr.

BrauchtVerstrichene Zeit tracken, wait_time des Spawner-Timers zur Laufzeit anpassen.

PHASE 9

Platzhalter → echte Assets

Sprites vom Freund einsetzen, sobald verfügbar. Kein neues Konzept nötig.
